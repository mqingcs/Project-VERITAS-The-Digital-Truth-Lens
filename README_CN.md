# Project VERITAS: 数字真理透镜

> *Veritas vincit omnia.* (真理战胜一切。)

**Project VERITAS** 是一个“数字粗野主义”风格的浏览器扩展，旨在重建网络的信任与清晰度。它利用一个由专业 AI Agent 组成的蜂群来实时分析内容，检测逻辑谬误，提取事实声明，通过全网验证信息，并可视化知识的隐藏结构。

## 🏗️ 哲学：数字粗野主义

Veritas 拒绝“干净的企业风”美学。它拥抱 **数字粗野主义**：
*   **原始数据**：信息不加修饰地呈现。
*   **高对比度**：霓虹青 (#00F0FF) 和金色 (#FFD700) 对比深邃的虚空黑 (#050505)。
*   **功能至上**：每一个像素都为揭示真理而生。
*   **霓虹仪式**：激活时触发呼吸般的“霓虹光环”和 CRT 扫描线，标志着系统已苏醒。

## 🧠 Agent 蜂群

Veritas 不是聊天机器人。它是一个由四个专业 Agent 组成的协调蜂群：

### 1. 🛡️ VELOX (哨兵)
*   **模型**: Gemini 2.5 Flash-Lite
*   **角色**: 高速噪音过滤和谬误检测。
*   **能力**: 识别 *人身攻击*、*稻草人谬误*、*煤气灯效应* 和情绪操纵。

### 2. ⚖️ RATIO (分析师)
*   **模型**: Gemini 2.5 Flash
*   **角色**: 精确事实提取。
*   **能力**: 分离原子声明，链接实体，并保留原始语言以保证搜索准确性。

### 3. 🔍 VERITAS (调查员)
*   **模型**: Gemini 2.5 Flash + Google Search Grounding
*   **角色**: 实时网络验证。
*   **能力**: 将声明与可信来源（政府/教育 > 媒体）进行交叉引用，构建知识图谱，并严格避免背诵。

### 4. 💬 COMMANDER (编排者)
*   **模型**: Gemini 2.5 Flash
*   **角色**: 中央枢纽和用户界面。
*   **能力**: 执行复杂的自主研究链（“找到 X，验证 Y，报告 Z”），管理 DOM，并适应用户意图。

## ✨ 核心特性

### 👁️ 真理扫描 (`Alt + Shift + V`)
即时分析当前页面。
*   **蓝色轮廓**: 逻辑谬误。
*   **青色下划线**: 事实声明。
*   **颜色编码验证**:
    *   ✅ **绿色**: 已验证事实。
    *   ❌ **红色**: 被揭穿/虚假。
    *   ⚠️ **黄色**: 有争议。

### ⚛️ 增强全息卡片
悬停在任何高亮元素上以打开一个可拖动的 6 标签页仪表盘：
*   **风险仪表**: 实时误导评分 (0-100)。
*   **谬误**: 逻辑错误的详细分解。
*   **验证**: 证据链和来源链接。
*   **Commander 聊天**: 关于特定元素的上下文感知问答。

### 🕸️ 3D 知识图谱 (“上帝模式”)
在完全交互式的力导向 3D 空间中可视化声明、实体和来源之间的隐藏连接。
*   **聚焦模式**: 隔离特定节点。
*   **智能搜索**: 即时在网络中查找实体。
*   **物理引擎**: 节点根据语义关系相互吸引/排斥。

## 🚀 快速开始

### 先决条件
*   **Node.js**: v18+
*   **pnpm**: 推荐。
*   **Google Gemini API Key**: 必需。

### 安装

1.  **克隆 & 安装**:
    ```bash
    git clone https://github.com/your-repo/project-veritas.git
    cd project-veritas
    pnpm install
    ```

2.  **配置环境**:
    创建一个 `.env` 文件：
    ```env
    PLASMO_PUBLIC_GEMINI_API_KEY=your_api_key_here
    ```

3.  **运行开发服务器**:
    ```bash
    pnpm dev
    ```

4.  **在 Chrome 中加载**:
    *   前往 `chrome://extensions` -> 启用“开发者模式”。
    *   点击“加载已解压的扩展程序” -> 选择 `build/chrome-mv3-dev`。

## ⚡ 高级用法

### 自主研究链
通过 `Alt + Shift + C` 给 Commander 下达复杂的多步骤指令：
> *“找出页面上关于‘核能’的所有声明，根据 IAEA 官方报告进行验证，并总结误解。”*

### Agent 重任务化 (Retasking)
如果蜂群犯错，纠正它：
> *“你漏掉了第二段中的声明。再看一遍。”* -> Commander 将重新规划并重新执行。

### “终止开关”
点击 Commander 面板中的 **STOP** 以立即终止任何自主循环。

## 🚧 路线图 (Roadmap)

### 第一阶段：关键修复与紧急功能
- [ ] **本地化**: 确保全息卡片语言适应用户设置。
- [ ] **Bug 修复**: 修复混合谬误和验证时显示的 `Confidence: NaN%`。
- [ ] **高亮**: 实现 DOM 标注的 100% 成功率。
- [ ] **用户体验**: 修复任务期间进度条卡在 0 的问题。
- [ ] **错误处理**: 为重复搜索错误添加特定提示。

### 第二阶段：架构与统一
- [ ] **统一 Commander**: 将全息卡片的聊天与全局 Commander 合并为单一上下文窗口。
- [ ] **扩展 API**: 实现 API 以允许更多自主 Agent 操作。
- [ ] **模型升级**: 一旦发布，立即迁移到 **Gemini 3.0 Flash**。

### 第三阶段：UI/UX 全面革新
- [ ] **视觉打磨**: 实现“跑马灯”滚动效果和精致的侧边栏设计。
- [ ] **设计一致性**: 统一所有弹出窗口、模态框和对话框，严格遵循“数字粗野主义”和全息 UI 语言。
- [ ] **布局**: 将图谱卡片中的“全屏”按钮移至右侧，以获得更好的人体工程学体验。

### 第四阶段：性能与经济
- [ ] **延迟**: 大幅减少搜索和分析时间。
- [ ] **计费系统**: 基于 Gemini API 定价的实时成本计算。
- [ ] **预算模式**: “低功耗”设置（跳过复杂的“思考”循环，使用更便宜的模型）。

### 第五阶段：核心大脑 (GraphRAG)
*超越向量相似性，迈向真正的基于图谱的检索增强生成。*

- [ ] **集成**: 将逻辑谬误和验证结果直接嵌入知识图谱。
- [ ] **深度挖掘**: “Deep Dive”操作应在图谱中动态生成新节点。
- [ ] **图谱查询**: 允许用户 *与* 图谱聊天（例如，“查找实体 A 和事件 B 之间的联系”）。
- [ ] **愿景**:
    *   *传统 RAG*: 告诉你“文章说了什么”。
    *   *GraphRAG*: 通过遍历隐藏链接告诉你“为什么这很重要”（例如，将股价下跌与 3 个月前供应商的火灾联系起来）。
    *   *哲学*: “只有看到联系，我们才能摆脱单一视角的黑暗。”
